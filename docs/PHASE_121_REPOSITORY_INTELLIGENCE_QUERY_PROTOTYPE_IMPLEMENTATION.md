# Phase 121E - Repository Intelligence Read-Only Query Prototype

## 1. Purpose

Phase 121E implements the first Repository Intelligence Query Layer
prototype. The prototype provides deterministic, read-only querying of
existing Repository Knowledge Snapshot artifacts generated by Track
120.

The implementation supports only Repository Knowledge Snapshot
artifacts whose executable schema version is:

```text
119O.1.0-json-schema
```

No additional Repository Intelligence artifact family is supported.

## 2. Implementation Overview

Implemented a narrow query package under
`src/pcae/repository_intelligence/query/`:

- `snapshot_loader.py`: read-only JSON loading and compatibility
  verification for Repository Knowledge Snapshot artifacts.
- `query_request.py`: bounded structured query request representation
  and request validation.
- `query_engine.py`: deterministic lookup evaluation and result
  assembly.
- `attribution.py`: attribution extraction and fail-closed
  attribution checks for content-bearing records.
- `query_result.py`: deterministic result container.
- `result_formatter.py`: deterministic JSON formatting.
- `__init__.py`: package exports.

Added the minimal CLI surface:

```text
pcae repository-intelligence query --snapshot PATH [target] [--json|--pretty]
```

Supported target flags:

- `--entity`
- `--capability`
- `--contract`
- `--attribution`
- `--limitations`
- `--boundary`

No query language, parser grammar, interactive mode, REST surface, API
server, runtime plugin, or additional Repository Intelligence generator
was introduced.

## 3. Query Pipeline

The implemented pipeline follows the 121D plan:

1. **Query request intake**: CLI or tests provide a bounded structured
   request.
2. **Request validation**: unsupported categories and missing required
   targets fail closed.
3. **Snapshot loading**: reads an existing JSON artifact from the
   declared snapshot path.
4. **Snapshot compatibility verification**: accepts only
   `119O.1.0-json-schema`; missing, malformed, or unsupported versions
   fail closed.
5. **Query evaluation**: performs exact deterministic lookup over
   snapshot content.
6. **Attribution preservation**: preserves embedded Source Attribution
   Records or capability source attribution for returned
   content-bearing records.
7. **Limitation propagation**: carries snapshot-level and record-level
   limitations into results, and adds query limitations for unknown or
   missing data.
8. **Boundary attachment**: preserves snapshot boundary disclosures and
   disclaimers in every result.
9. **Result assembly**: returns records, attribution, limitations,
   unknowns, source artifact metadata, query metadata, and determinism
   metadata.
10. **Result formatting**: produces stable JSON output with sorted
    keys.

## 4. Supported Query Categories

Implemented only the minimal deterministic subset authorized for 121E:

- **Entity lookup**: exact match by `entity_id`, `entity_name`, or
  `entity_path`.
- **Capability lookup**: exact match by `capability_id` or
  `capability_name`.
- **Architectural contract lookup**: exact match by `contract_id`,
  `contract_name`, or `contract_version`; absent optional contract
  sections return bounded unknown/missing-data results.
- **Attribution lookup**: returns attribution records for a matching
  entity, capability, or contract target.
- **Limitation lookup**: returns snapshot limitation records.
- **Boundary lookup**: returns snapshot boundary disclosures and
  disclaimers.

Unsupported query categories fail closed.

## 5. Attribution Behavior

Every returned content-bearing record preserves provenance:

- entity and contract records preserve their `source_attribution`
  arrays;
- capability records preserve their `capability_source`;
- attribution lookup returns the embedded Source Attribution Records
  themselves;
- all results include source artifact metadata: artifact id, artifact
  type, snapshot id, executable schema version, and repository commit.

If a content-bearing record selected for return lacks required
attribution, query execution fails closed rather than returning an
unattributed fact.

## 6. Limitation Behavior

Every query result includes deterministic limitations:

- snapshot-level limitations are propagated;
- record-level limitations are propagated for returned records;
- unknown or missing targets add query-specific `missing_data`
  limitations;
- unsupported or invalid requests fail closed before evaluation.

Limitations are never suppressed by formatting or compact output.

## 7. Boundary Disclosure Behavior

Every query result preserves snapshot `boundary_disclosures` and
`disclaimers`. Query results remain context only. They are not
Repository State, Evidence, Advisory output, Decision Evaluation,
execution authorization, or Repository Intelligence generation.

## 8. Schema Compatibility

Compatibility verification accepts only:

```text
snapshot_identity.executable_schema_version == "119O.1.0-json-schema"
```

The loader fails closed for:

- missing snapshot file;
- invalid JSON;
- non-object JSON root;
- missing or invalid `snapshot_identity`;
- unsupported executable schema version;
- missing required query input fields.

No schema migration, version negotiation, compatibility table,
validator authority, or field remapping was implemented.

## 9. Deterministic Guarantees

Equivalent snapshot plus equivalent query produces equivalent logical
result.

The implementation uses:

- exact field matching only;
- deterministic record ordering;
- deterministic attribution ordering;
- deterministic limitation ordering;
- stable JSON formatting with sorted keys.

It uses no randomness, probabilistic ranking, AI inference, semantic
summarization, filesystem-order-dependent results, network calls,
hidden mutable caches, or time-dependent result content.

## 10. Read-Only Guarantees

The query implementation never:

- modifies Repository Knowledge Snapshot artifacts;
- generates Repository Intelligence;
- rescans repository contents;
- executes repository code;
- invokes shell commands;
- invokes subprocesses;
- invokes AI providers;
- invokes external APIs;
- mutates runtime state;
- mutates Repository State;
- mutates Evidence;
- invokes Advisory;
- performs Decision Evaluation;
- performs graph traversal;
- performs dependency analysis;
- performs change impact analysis;
- plans or authorizes execution.

Focused tests verify the queried snapshot file hash is unchanged before
and after query execution.

## 11. Unknown and Fail-Closed Handling

The prototype returns deterministic unknown/missing-data results for:

- unknown entity;
- unknown capability;
- absent optional contract section;
- missing data in supported sections.

It fails closed for:

- unsupported query category;
- missing required query target;
- missing snapshot;
- corrupted snapshot;
- unsupported executable schema version;
- missing required attribution on a content-bearing return.

No inference is used to fill missing data.
