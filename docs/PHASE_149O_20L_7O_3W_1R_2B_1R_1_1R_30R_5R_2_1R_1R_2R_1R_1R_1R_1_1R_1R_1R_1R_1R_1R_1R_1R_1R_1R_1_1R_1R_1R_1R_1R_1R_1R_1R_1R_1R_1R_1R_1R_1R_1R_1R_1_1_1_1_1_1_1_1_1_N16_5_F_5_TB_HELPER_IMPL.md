### Protocol schema and dispatch (`hpac_pawa_helper_protocol.py`)
- Closed `HPAC-PAWA-HELPER-REQUEST/1.0` and `HPAC-PAWA-HELPER-RESPONSE/1.0` frozen dataclasses. `HelperRequest.from_mapping` is the sole production-facing ingestion path and fails closed on unknown or missing fields.
- Closed 5-member `HelperOperation` enum (`admin_mutation`, `certification_write`, `certification_read`, `ceremony_entry`, `presentation_evidence_write`) — asserted `len == 5` at import time.
- Closed 5-member `CertificationRole` enum; `hpac_lifecycle_terminator` asserted absent.
- Closed 9-member typed read-record vocabulary (`CLOSED_READ_RECORD_TYPES`); closed 7-member admin-mutation class set (`CLOSED_ADMIN_MUTATIONS`), mirroring the existing `PawaOperation` values by literal string, not re-derived.
- `validate_and_admit`: explicit conjunctive admission (protocol/schema version, operation membership, per-operation `operation_version`, role-only-for-certification_write, replay/freshness, a forbidden-free-form-key scan on `operation_params` rejecting `path`/`shell`/`command`/`executable`/etc.).
- `dispatch`: explicit closed-mapping table, asserts the handler mapping is exactly the 5 closed operations (no more, no fewer) on every call — no `getattr`/reflection anywhere in the dispatch path.
- `HelperStateMachine`: forward-only transition enforcement over the frozen ordered sequence; `assert_may_start_mutation_attempt` is the concrete no-auto-retry enforcement point once `MUTATION_ATTEMPT_STARTED` is crossed.
- `ReplayLedger`: `fresh` / `consumed` / `duplicate_in_flight` / `expired` / `conflicting` outcomes; `release_in_flight_without_consuming` is only valid before the no-retry boundary.
- `EvidenceStager`: stage-before-mutate (`stage`, raises before any mutation on failure), finalize-after-commit (`finalize`), `is_indeterminate` surfaces the post-commit/pre-finalize uncertain state rather than collapsing it into an ordinary rejection.
- `response_leaks_authority` / `_value_leaks_authority`: recursive scan of every response field name and nested string value/key against a forbidden-authority-token set (`HPACWriterCapability`, `HPACStoreAuthority`, `ProductionWriterHandle`, `capability_token`, `seal`, etc.); `dispatch` asserts this scan is clean on every response before returning it.
- The closed 21-value `pawa_failure_code` vocabulary is re-stated verbatim (not duplicated as a new vocabulary) in `PAWA_FAILURE_CODES`; a test independently imports `hpac_protected_admin_writer.PAWA_FAILURE_CODES` and asserts byte-for-byte tuple equality. `hpac_pawa_helper_protocol.py` does **not** import `hpac_protected_admin_writer` (verified by `grep`).

### OS-level primitives (`hpac_pawa_helper_os.py`)
- `verify_helper_executable`: opens the candidate with `O_NOFOLLOW`, then evaluates — on that **one** already-open descriptor — regular-file, exactly-one-hard-link, expected-owner, expected-mode (`0755`), optional same-device-as-protected-root, and complete-byte SHA-256, all conjunctively; fails closed (raises `HelperProtocolError`) on any single mismatch.
- `execute_verified`: same-file-object anti-TOCTOU execution. **Linux:** forks and re-execs through `/proc/self/fd/<fd>` in the child — resolves to the same file description regardless of any subsequent directory-entry mutation (rename/replace/symlink-substitution of the original path). **macOS and any other platform:** raises `UnsupportedPlatformProfile` rather than falling back to a path-based exec — a disclosed, genuine platform gap (see §6 below), not a silent weakening.
- `OneShotChannel`: `AF_UNIX` socket under a `0700` directory, `0600` socket file, `listen(1)`, single `accept_one()` (raises on reuse), removes the socket path on close.
- `get_kernel_peer_credential`: Linux via `SO_PEERCRED` (`struct.unpack("3i", ...)`), macOS via `getpeereid` through `ctypes.CDLL(None)`; any other platform raises `UnsupportedPlatformProfile`. Never derives identity from anything the peer sent over the channel.
- `authenticate_peer`: peer uid must equal the deployment-owner uid; peer uid must not equal the configured-agent principal's uid (when supplied) — both required conjuncts, evaluated before operation admission.
- Imports `resolve_configured_agent_identity` from the existing, unmodified `pcae.core.hpac_pawa_agent_exclusion` module (the HPAC-PAWA-AGENT-EXCLUSION/1.0 resolver already relied on by `hpac_protected_admin_writer`) rather than re-deriving configured-agent resolution. Does **not** import `hpac_protected_admin_writer`.

### Bounded per-operation handlers (`hpac_pawa_helper_operations.py`)
- `admin_mutation`: metadata-only; does not create/copy helper executable bytes, chmod/chown arbitrary paths, or accept an arbitrary filesystem target.
- `certification_write`: gated on the closed 5-role set; bounded foundation only, no real orchestration.
- `certification_read`: restricted to the closed 9-member typed read-record set; returns typed record contents, never a store handle.
- `ceremony_entry`: bounded, explicitly non-authoritative hand-off; deterministic test stand-in only.
- `presentation_evidence_write`: bounded operation shape consistent with `HPAC-PPA-001` v2.0; no live write, no generic evidence-writer handle exposed.
- All five run against an injected `ProtectedStoreFoundation` — a NON_REAL, in-memory stand-in never wired to `<HPAC_PROTECTED_ROOT>` by this phase.

## 6. Disclosed gap (not a silent weakening)

The same-file-object anti-TOCTOU execution property (`execute_verified`) and the OS peer-credential primitive (`get_kernel_peer_credential`) are both implemented for Linux (the deployment target) and, for peer credentials only, macOS (the development host, via `getpeereid`). `execute_verified` has **no** substitution-free exec primitive available through the Python standard library on macOS, and correctly raises `UnsupportedPlatformProfile` (fail-closed, per HPAC-PAWA-HELPER-REQ-104) rather than falling back to a path-based `exec` that would reopen the TOCTOU window. This is a genuine, disclosed platform gap, not a defect: the contract's actual deployment target is Linux, and the frozen property is preserved there.
