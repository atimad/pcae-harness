## 4. MATERIAL FINDING — consumer authenticity is spoofable (BLOCKING)

**This is the dispositive finding of this IV.**

`recognized_certification_read_authority(...)` (the new §33B factory) derives its caller identity via `caller_module = _detect_caller_module(_caller_module)` (`hpac_protected_admin_writer.py:2351`). `_detect_caller_module` (`hpac_protected_admin_writer.py:495-504`):

```python
def _detect_caller_module(explicit: Optional[str]) -> str:
    if explicit is not None:
        return explicit
    stack = inspect.stack()
    ...
```

If the caller supplies `_caller_module` explicitly, that value is returned **verbatim, unconditionally, before the real call stack is ever consulted.** The subsequent §38B/step-9 authorization check (inside `_run_recognition_sequence`) is a pure `caller_module not in authorized_consumers` string membership test against `READ_AUTHORITY_CONSUMERS == {"pcae.core.hpac_certification_coordinator"}`. There is no runtime mechanism binding the asserted `caller_module` string to the genuine identity of the calling code — the check reduces to: does the caller's *self-reported* string match the allowed string.

**Live reproduction (not inference):** a fresh IV test suite (`tests/test_phase_..._1r_1r_2r_1r_1r_1r_1_..._n16_5_f5b1_iv.py`) was authored for this phase. Its own test module — a genuinely unauthorized caller, independently confirmed not to be in `READ_AUTHORITY_CONSUMERS` and correctly denied when it calls the factory without any override (`test_20_baseline_this_module_is_genuinely_unauthorized`) — successfully obtains a fully working `CertificationReadAuthority` handle by passing `_caller_module="pcae.core.hpac_certification_coordinator"` as an ordinary public keyword argument (`test_21_arbitrary_caller_spoofs_coordinator_identity_and_succeeds`). No reflection, no private-attribute access, no monkeypatching of production code was used. The forged handle is fully functional: `read_principal_and_credential()` returns the real bound principal and credential records.

**The predecessor's own positive evidence is built on the same seam.** Independent inspection of the predecessor's committed test file (`tests/test_phase_..._n16_5_f5b1_impl.py`) confirms its `Rig.ra()` helper — the basis for every "authorized consumer accepted" test, including `test_12_authorized_consumer_accepted` — passes `_caller_module=COORDINATOR_MODULE` explicitly on every call (`test_22_predecessors_own_positive_tests_rely_on_the_same_spoof_seam`, confirmed by `git grep` of the literal string). The predecessor's suite never exercises the factory via genuine, un-overridden call-stack detection from inside the real coordinator; its evidence for "sole authorized consumer" is produced using the exact mechanism this IV finds spoofable.

**The only existing control is static, not a runtime boundary.** A guard test elsewhere in the repo (`test_90_read_authority_symbol_not_imported_by_agent_reachable_code` and siblings) performs a source-scan (`git grep`) asserting no non-test module *currently checked into this repository* passes `_caller_module`. This detects an accidental production caller at commit time; it does nothing to prevent a genuinely hostile or simply out-of-scan caller (a future plugin, an untracked script, dynamically loaded code, or any code path the scan doesn't cover) from calling the exported, non-underscored-away, publicly documented `recognized_certification_read_authority` with the spoofed argument at runtime.

**Provenance, not a new defect, but not excused.** `git log -S_caller_module -- src/pcae/core/hpac_protected_admin_writer.py` confirms this exact seam and `_detect_caller_module` predate I_ENTRY — it is shared, verbatim, with the pre-existing `production_writer` and `certification_writer` factories. F-5-B1's repair did not introduce this defect; it reused the existing helper unmodified for the new read-authority path. Per this IV's governing spec (§62/§92 item 13/§106), that provenance does not change the verdict for F-5-B1's own factory: the requirement is that "CALLER-SUPPLIED CONSUMER STRING ALONE" be "INSUFFICIENT," and it is not.

**No repair was attempted in this phase.** Per governing scope, this IV phase does not modify `src/pcae`, `scripts/`, or contract text, and does not repair the defect.
