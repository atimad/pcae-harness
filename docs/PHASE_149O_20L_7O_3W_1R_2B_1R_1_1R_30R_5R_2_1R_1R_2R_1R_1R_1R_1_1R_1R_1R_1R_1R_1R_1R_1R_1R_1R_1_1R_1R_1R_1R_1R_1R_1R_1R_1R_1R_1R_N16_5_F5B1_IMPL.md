## 6. F-5-B1 mechanical repair (the core proof)

Root cause: `HPACStoreAuthority._validate_production_boundary` keys the negative boundary check off `_configured_agent_identity` when bound, and off the live invoking process's identity (`os.geteuid()`) otherwise. Under real deployment-owner `sudo`/root invocation, the live process genuinely *can* write the protected root, so an unbound authority's boundary check fails closed for *any* protected-store read — this is the actual F-5-B1 mechanism, not merely a theoretical description of it.

`recognized_certification_read_authority` binds the resolved `ConfiguredAgentAuthorityIdentity` **before** the first protected-store canonical read, so the boundary check is evaluated against the configured agent (who genuinely lacks write access) rather than the ambient root/sudo identity.

Proof (`tests/test_phase_..._n16_5_f5b1_impl.py`, section G):

- `test_60`: with `_current_agent_identity` mocked to `(0, ∅)` (ambient root) and a probe where uid 0 can write the fixture root, a **direct, unbound** `HumanPrincipalRegistryStore(authority).resolve_canonical_principal(...)` call raises `HPACAuthorityError`.
- `test_61`: under the identical mocked ambient-root identity, `recognized_certification_read_authority(...)` **succeeds** and its `read_principal_and_credential()` returns the correct record.
- `test_62`: after the recognized session, a **fresh, still-unbound** authority instance under the same ambient identity is **still denied** — the bind does not globally trust root.
- `test_63`: a fresh, unrelated authority instance's `_configured_agent_identity` is `None` — no cross-instance leak.
- `test_64`: a failed accessor call cannot leave a stale bind on a later call, because each call constructs a fresh `HPACStoreAuthority` instance (§33 step 1).

**Mutation sanity check performed during this phase:** the `_bind_configured_agent_identity(...)` call was temporarily removed and the test suite re-run — `test_61`/`test_62`/`test_63`/`test_64` failed exactly as expected (`HPACAuthorityError: production HPAC root is not protected from the configured agent principal`), confirming the tests are load-bearing and not vacuously green. The fix was then restored and the full suite re-verified green.
