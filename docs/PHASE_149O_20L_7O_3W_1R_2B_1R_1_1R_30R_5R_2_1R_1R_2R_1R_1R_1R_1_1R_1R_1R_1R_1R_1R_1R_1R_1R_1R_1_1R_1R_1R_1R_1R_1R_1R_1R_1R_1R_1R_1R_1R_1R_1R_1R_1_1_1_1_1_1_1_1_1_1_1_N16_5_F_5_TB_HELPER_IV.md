## 3. Independent verification test evidence

New file: `tests/test_phase_149o_20l_7o_3w_1r_2b_1r_1_1r_30r_5r_2_1r_1r_2r_1r_1r_1r_1_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1r_1_1_1_1_1_1_1_1_1_1_1_n16_5_f_5_tb_helper_iv.py`
— 7 tests, all disposable (subprocess-isolated interpreters, no live
protected root, no real ceremony), **7 passed**:

1. `test_replay_after_restart_cross_process_confirms_blocking_defect` —
   **the authoritative reproduction.** Two genuinely separate OS processes
   (`subprocess.run([sys.executable, "-c", ...])`, not two objects in one
   process): process A constructs a fresh `ReplayLedger()`, admits+consumes
   a fixed `(request_id, nonce)` mutating request, exits. Process B is a
   brand-new interpreter with its own fresh `ReplayLedger()` and evaluates
   the byte-identical request. **Result: process B reports `FRESH`.** This
   independently reproduces **REPLAY-AFTER-RESTART**: a consumed mutating
   `(request_id, nonce)` becomes fresh again once a new helper process
   starts, because no durable state survives the process boundary in the
   current foundation.
2. `test_response_loss_cross_process_does_not_prevent_resurrection_today` —
   same defect, response-loss framing: process A commits, "response lost";
   fresh process B still reports `FRESH`.
3. `test_indeterminate_crash_cross_process_does_not_prevent_resurrection_today`
   — same defect, crash-before-terminal-disposition framing: process A
   crosses the no-retry boundary (in-flight) without ever calling
   `mark_consumed`, then exits ("crashes"); fresh process B still reports
   `FRESH` — in fact worse than the consumed case, since an in-flight,
   possibly still-live first attempt can be raced against.
4. / 5. Structural confirmation via `inspect.getsource` that `ReplayLedger`
   and `ProtectedStoreFoundation` contain no filesystem/network I/O markers
   anywhere in their bodies, and that their constructors take no durable-
   location argument — makes "process-local in-memory" source-verifiable,
   not merely inferred from the three dynamic tests above.
6. `test_execute_verified_fails_closed_on_real_current_non_linux_platform` —
   confirms, on the real (unpatched) current platform, `execute_verified`
   still raises `UnsupportedPlatformProfile` with no substitution-free exec
   primitive available. Closes a gap: the existing suite only proves this
   after `monkeypatch`-ing `sys.platform` to a synthetic value.
7. `test_verified_executable_fd_is_process_local_not_a_portable_authority_token`
   — confirms the OS-level "authority" object (`VerifiedExecutable.fd`) has
   no serialization/reconstruction method and cannot become a bearer token
   smuggled across the process boundary. This is the **correct** half of
   "authority dies / history persists" — only the *history* half (item 1-3
   above) is broken.
